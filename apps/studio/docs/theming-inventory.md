# Theming inventory

Every theming and visual decision in the repo and in the Omarchy surfaces it themes, checked against the Material 3 snapshot in [material-3/](material-3/README.md) (content version 2026-09-23). Compiled 2026-10-12.

Verdicts: **✓** matches the spec, **✗** differs from it, **~** partly matches, **—** M3 has no equivalent, **?** not checked yet.

## 1. How theming flows

| Stage   | Where                                                   | What                                                                                                                                                                                                                                                                                            |
| ------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seed    | Studio, Theme page                                      | Wallpaper from a file (input exists but isn't wired), Wallhaven or Pexels. A worker quantizes it to a source colour plus ranked hues.                                                                                                                                                           |
| Scheme  | `packages/theme-engine/src/scheme.ts`                   | `@material/material-color-utilities` `DynamicScheme`. The kind, dark/light and contrast level (−1…1) come from Studio.                                                                                                                                                                          |
| Palette | `scheme.ts`, `surfaces.ts`, `ansi.ts`                   | `OmarchyColors`: the 26 Omarchy keys plus every Material role as `omaterial_*`.                                                                                                                                                                                                                 |
| Files   | `theme-engine/src/theme/files/*`                        | `colors.toml`, `hyprland.lua`, 13 `shell.*.toml`, written to `~/.config/omarchy/themes/omaterial-dev/`.                                                                                                                                                                                         |
| Apply   | Rust `set_theme` → `omarchy theme set omaterial-dev`    | `omarchy-theme-set` stages the theme, then `omarchy-theme-set-templates` renders `default/themed/*.tpl` for every file the theme doesn't ship. Each `shell.<section>.toml` replaces that whole `[section]` in the generated `shell.toml`. The shell gets the colours and `shell.toml` over IPC. |
| Tokens  | `packages/tokens`, `~/.config/omarchy/stef/tokens.json` | Gaps, border, blur, shadow, motion scheme, expo and periphery layout. Plugins read them live (`Tokens.qml`). `hyprland.lua` renders them, but Studio always renders `defaultTokens` (see §9).                                                                                                   |

Where the Omarchy side lives (all under `/usr/share/omarchy`):

- Shell singletons: `shell/Commons/Color.qml`, `Style.qml`, `Border.qml`.
- Templates: `default/themed/*.tpl`, rendered by `bin/omarchy-theme-set-templates`.
- Colour-key derivation: `bin/omarchy-theme-color`.
- Default Hyprland look: `default/hypr/looknfeel.lua`. The theme's `hyprland.lua` loads at the end of `default/hypr/omarchy.lua`, before the user's `~/.config/hypr/looknfeel.lua`.

Keys Omarchy derives itself (`bin/omarchy-theme-color`):

- `selection_background` = selection
- `selection_foreground` = bright_foreground
- `purple` = magenta
- `color0`–`color15` (ANSI), with `color8` = muted
- `cursor` = bright_foreground

`hyprland_active_border` and `hyprland_inactive_border` are never set. That's harmless for Hyprland, because the theme ships its own `hyprland.lua`, but `shell.toml.tpl`'s `[hyprland]` default falls back to `accent`. Omaterial overrides that section anyway.

Apps themed from these keys through the templates, so they follow the mapping above rather than Material roles: alacritty, btop, chromium, Claude Code, foot, ghostty, gum, helix, hermes, hyprland share-picker CSS, keyboard RGB, kitty, neovim, obsidian, pi, t3code, VS Code.

## 9. Known inconsistencies

1. **Studio themes ignore `tokens.json`.** `ThemeTokens` defaults to `defaultTokens` and nothing provides it (`theme/shared.ts:20`; it isn't exported from the package index). The Tokens page says the opposite.
2. **Border angle split:** `hyprland.lua` uses the token, but `shell.hyprland.toml` and `shell.notifications.toml` hardcode `55deg`.
3. **Unused code:** `template.ts` (only its test uses it) and `files/foot.ini.ts` (not in `makeThemeWriters`).
4. **`omaterial_*` in `colors.toml` are decimal ARGB,** not hex.
5. **Expo's scrim cap** (0.3) silently overrides the theme's 0.32.
6. **Periphery springs** don't follow `motion.scheme` (already in `plans/open-tasks.md`).
7. **No corner radius anywhere** on the desktop: Omaterial never sets `decoration:rounding`, so the shell's radius is 0 too.
